# V12.12-A — Especificación mobile-first AppPromos

## Estado

Documento de especificación. No implementa código de navegación todavía.

## Objetivo

Rediseñar AppPromos como una app nacida para celular, no como una web achicada.

La base de diseño debe ser el celular real del carnicero argentino:

- Android gama media / entrada.
- Samsung Galaxy A06 / A15 como referencia principal.
- Xiaomi Redmi 14c / Moto G04s como alternativas frecuentes.
- Pantalla vertical.
- Uso con una mano.
- Trabajo de mostrador, apuro, interrupciones, poca paciencia y necesidad de vender ya.

Frase guía:

> La app no se achica para celular. La app nace para celular.

## Principios de diseño V12.12

1. La navegación principal debe estar cerca del pulgar.
2. El cuerpo de la app debe quedar para vender.
3. Carniza orienta, pero no tapa.
4. La Nelly aparece solo cuando hay que resolver cuenta, pago o acceso.
5. El header se compacta o se oculta cuando estorba.
6. Cada pantalla debe tener una intención principal.
7. Menos texto en pantalla, más acción clara.
8. Botones grandes, fáciles de tocar.
9. Nada de acciones críticas escondidas arriba.
10. Nada de mensajes internos de desarrollo en la UI.

## Regla madre

```txt
La botonera mueve.
Carniza orienta.
El cuerpo vende.
```

## Botonera inferior base

La navegación mobile principal debe ser una botonera inferior fija:

```txt
[Inicio] [Precios] [Vender] [WhatsApp] [Más]
```

Debe ser visible en mobile y pensada para tocar con el pulgar.

### Inicio

Vuelve al tablero principal.

Debe responder rápido:

- qué puedo hacer ahora;
- qué acción comercial conviene;
- cómo salgo vendiendo sin pensar demasiado.

Inicio no debe llenarse de módulos secundarios ni avisos gigantes.

### Precios

Abre **Cambiar precios**.

Mensaje clave dentro de Precios:

```txt
Poné precio a lo que vendés.
Lo que no vendés, dejalo en 0 y no aparece en tu web.
```

Criterio de pantalla:

- buscador visible;
- rubros fáciles de tocar;
- lista compacta;
- guardar cambios fácil;
- feedback claro cuando un precio se guarda.

### Vender

Es el corazón comercial.

Al tocar **Vender**, debe abrir un menú simple:

```txt
Oferta rápida
Oferta con descuentos
Vender urgente
```

Definición:

- **Oferta rápida:** armar y mandar ya.
- **Oferta con descuentos:** ajustar kilos, descuentos y precio final.
- **Vender urgente:** mover mercadería rápido, sin decir “liquidación” al cliente final.

Regla:

```txt
Vender = acción comercial inmediata.
```

### WhatsApp

Acceso rápido a la salida comercial.

Puede servir para:

- enviar última oferta lista;
- retomar oferta pendiente si existe;
- copiar mensaje;
- abrir WhatsApp de venta;
- explicar que primero hay que armar una oferta si no hay nada listo.

Si no hay oferta lista, debe decir algo simple:

```txt
Primero armá una oferta y después la mandás por WhatsApp.
```

### Más

Guarda lo que no debe competir con vender:

```txt
Mi cuenta
Mi web
Ofertas guardadas
Competencia
Ayuda
Panel Admin, si corresponde
Cerrar sesión
```

Regla:

```txt
Más = administración, configuración y módulos secundarios.
```

## Carniza en mobile

Carniza no debe competir con la botonera inferior.

Debe ser una ayuda contextual, no otra navegación principal.

### Rol

Carniza debe:

- sugerir el próximo paso útil;
- ayudar a vender;
- orientar cuando hay duda;
- ofrecer acciones comerciales según contexto;
- no tapar precios, botones, totales ni mensajes operativos.

### Ubicación sugerida

- chip flotante pequeño sobre la botonera inferior;
- o botón compacto lateral que no tape acciones;
- nunca una card grande fija en el cuerpo principal.

### Acciones mínimas de Carniza

Carniza ya debe mantener navegación segura:

```txt
Armar oferta
Vender urgente
Ir a WhatsApp
Volver a Inicio
Salir de la demo / Cerrar sesión
```

En V12.12 debe convivir con la botonera sin duplicar ruido.

### Regla de prioridad

```txt
Primero feedback operativo.
Después Carniza.
```

Si aparece un mensaje importante, total, botón de guardar, CTA de WhatsApp o alerta de cuenta, Carniza no debe taparlo.

## La Nelly en mobile

La Nelly aparece para cuidar/resolver.

No debe competir con Carniza.

### Regla

```txt
Si aparece La Nelly, Carniza se esconde o se minimiza.
```

### Ubicación sugerida

- chip flotante abajo a la izquierda;
- cartelito/globito simple al tocar;
- CTA claro: **Resolver ahora**.

### Casos de aparición

- pago pendiente;
- pago vencido;
- acceso pausado;
- prueba por vencer;
- situación sensible de cuenta.

## Header mobile

El header actual debe compactarse para mobile.

### Debe mostrar lo mínimo

- marca / AppPromos;
- estado compacto si corresponde;
- no llenar la parte superior de botones.

### Acciones que deben moverse a Más

- Cerrar sesión;
- cuenta;
- ayuda;
- módulos secundarios;
- Panel Admin si corresponde.

## Modo foco

En flujos comerciales, el header superior puede compactarse u ocultarse para ganar espacio.

Pantallas candidatas:

```txt
Crear oferta
Oferta rápida
Oferta con descuentos
Vender urgente
Oferta lista
Cambiar precios
WhatsApp final
```

### Regla del modo foco

Cuando el carnicero está vendiendo, la pantalla debe mostrar lo necesario para avanzar.

Debe tener:

1. acción principal;
2. acción secundaria si hace falta;
3. volver / ajustar;
4. salida segura.

No debe tener decoración, textos largos ni navegación que robe espacio.

## Pantallas críticas

### Inicio mobile ideal

Debe concentrarse en acciones:

```txt
¿Qué querés hacer ahora?

Actualizar precios
Crear oferta
Vender urgente
```

Resumen mínimo:

```txt
Productos cargados · Ofertas guardadas · Web pendiente si corresponde
```

No debe tener cards gigantes que tapen el flujo comercial.

### Cambiar precios

Debe ser una pantalla de trabajo rápido:

- buscador;
- filtros por rubro;
- filas compactas;
- precio editable grande;
- guardar cambios accesible;
- tip de productos con precio 0.

### Vender

Debe abrir el selector:

```txt
Oferta rápida
Oferta con descuentos
Vender urgente
```

Debe ser una decisión de 1 toque.

### Oferta rápida

- elegir productos rápido;
- ver total claro;
- revisar;
- enviar por WhatsApp.

### Oferta con descuentos

- mostrar descuento en plata, no solo porcentaje;
- mantener total final visible;
- evitar filas gigantes;
- no explicar descuentos al cliente final por WhatsApp.

### Vender urgente

Lenguaje interno para carnicero:

```txt
Vender urgente
Producto atrasado
Sacar hoy
```

Lenguaje externo para cliente:

```txt
Oferta del día
Promo especial
Combo de hoy
Hasta agotar stock
```

Regla:

```txt
Internamente: urgencia.
Externamente: oportunidad.
```

### WhatsApp

El mensaje final debe ser legible, limpio y comercial.

No debe decir:

- liquidación;
- producto atrasado;
- mercadería para sacar;
- descuento aplicado si no suma a la venta.

Debe sonar a oportunidad.

## Panel Admin

El Panel Admin no entra en la misma prioridad mobile-first del carnicero.

Criterio:

```txt
App del carnicero = mobile-first.
Panel Admin = desktop/notebook-first, con adaptación mobile básica.
```

No forzar el Panel Admin a la misma botonera si eso rompe su uso operativo.

## Qué NO debe implementarse en V12.12-A

Este documento no implementa:

- botonera real;
- refactor de navegación;
- cambios de Firebase;
- cambios en registro;
- cambios en Web de Arranque;
- cambios en WhatsApp lógico;
- cambios en Panel Admin profundo.

## Plan recomendado de implementación

### V12.12-A — Especificación mobile-first

Este documento.

### V12.12-B — Botonera inferior base

- agregar botonera inferior mobile;
- mantener navegación actual como respaldo;
- conectar Inicio, Precios, Vender, WhatsApp y Más;
- no romper módulos existentes.

### V12.12-C — Vender como menú mobile

- Vender abre Oferta rápida / Oferta con descuentos / Vender urgente;
- evitar duplicaciones con Carniza;

### V12.12-D — Header compacto + modo foco

- compactar header en mobile;
- ocultar o reducir header en pantallas críticas;
- asegurar volver/salir.

### V12.12-E — Carniza contextual mobile

- Carniza como chip que orienta;
- no tapa botonera ni CTAs;
- si aparece La Nelly, Carniza se esconde.

### V12.12-F — QA mobile real

Probar en celular real o emulación aproximada:

- Samsung A06/A15 como referencia;
- Android Chrome;
- una mano;
- pantalla vertical;
- conexión normal.

## Checklist de aceptación V12.12 completa

1. El carnicero puede volver a Inicio desde cualquier lugar.
2. Puede ir a Precios con un toque.
3. Puede abrir Vender con un toque.
4. Desde Vender puede elegir Oferta rápida / Oferta con descuentos / Vender urgente.
5. Puede llegar a WhatsApp sin buscar botones arriba.
6. Puede cerrar sesión desde Más o Carniza sin perderse.
7. Carniza no tapa totales, precios, CTAs ni mensajes importantes.
8. La Nelly no compite con Carniza.
9. El header no roba espacio en flujos comerciales.
10. Crear oferta → WhatsApp sigue funcionando.
11. Vender urgente → WhatsApp sigue funcionando.
12. Cambiar precios sigue funcionando.
13. Web de Arranque no se rompe.
14. Landing mobile sigue mostrando Probar demo / Empezar gratis / Iniciar sesión.

## Decisión final

Antes de subir a `dev`, AppPromos debe sentirse como una app de mostrador real:

```txt
Android gama media.
Una mano.
Pocos toques.
Cero vueltas.
Vender primero.
```
