## Objetivo de esta versión

Ordenar la versión real del SaaS y avanzar con cambios chicos, seguros y comerciales sin romper Firebase, resolveSession ni la arquitectura multi-tenant.

Prioridad de producto:
1. Estabilidad.
2. Experiencia de usuario móvil.
3. Control SaaS comercial.
4. Escalabilidad multi-tenant.

## Arquitectura real confirmada

- Firebase Auth + Firestore.
- Frontend HTML + JS modular, sin frameworks.
- Multi-tenant: 1 usuario cliente = 1 carnicería.
- resolveSession determina modo de uso:
  - guest
  - client
  - superadmin
- BusinessStore mantiene en memoria la empresa activa, meta, state, productos, combos y datos asociados.
- El cliente no puede cambiar libremente de businessId.
- Superadmin puede administrar e impersonar empresas.

Planes reales:

No existe todavía plan premium en código.
No existe estado grace como estado principal. Si se usa período de gracia, debe representarse como billing.status = overdue + graceEndsAt.

## Trial real

Desde V11.4R, el alta de nuevas carnicerías crea trialEndsAt con fecha actual + 30 días.

Importante:
- Las carnicerías creadas antes de esta versión pueden tener trialEndsAt = null.
- Para esos casos, se recomienda corregir manualmente desde Admin o mediante migración controlada futura.

## Control SaaS de escritura

Desde V11.4R se agregó una guarda central de escritura:

public/js/services/write-guard-service.js

Regla comercial aplicada:
- El cliente puede entrar y consultar datos aunque esté vencido/suspendido.
- Si billing está overdue, trial vencido o suspended, el cliente NO puede guardar cambios.
- Si la empresa está disabled, suspended o inactive, el cliente NO puede operar módulos.
- Superadmin mantiene permiso de escritura para soporte y corrección operativa.

Esto mejora la lógica SaaS sin tocar Firestore Rules todavía.

## Decisión UX importante

La app está pensada para carnicerías que usan el celular mientras atienden, cobran, despostan, responden WhatsApp y modifican precios rápido.

Por eso la restricción de pago debe ser clara y no confusa:
- Se permite entrar.
- Se permite mirar información.
- Se bloquea solo el guardado.
- El mensaje debe explicar qué pasa y qué hacer.
- No se debe dejar al usuario en una pantalla rota o vacía.
