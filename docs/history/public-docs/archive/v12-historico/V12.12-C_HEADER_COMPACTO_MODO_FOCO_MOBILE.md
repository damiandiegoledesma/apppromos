# V12.12-C — Header compacto + modo foco mobile

## Objetivo

Dar el siguiente paso mobile-first después de la botonera inferior.

La app deja de comportarse como una web achicada y empieza a reservar la pantalla chica para la acción real del carnicero.

```txt
Arriba menos ruido.
Abajo navegación.
Centro acción.
```

## Qué cambia

### 1. Header mobile compacto

En celulares, el encabezado se reduce:

- logo más chico;
- título más compacto;
- subtítulo recortado;
- área de cuenta más estrecha;
- navegación superior de módulos oculta en mobile, porque ya existe botonera inferior.

### 2. Modo foco en acciones concretas

En mobile, el header se oculta en pantallas de acción:

- Cambiar precios;
- Crear oferta;
- Oferta rápida;
- Oferta con descuentos;
- WhatsApp.

Esto libera espacio para que el carnicero no tenga que pelearse con el header mientras vende.

### 3. Mantiene la botonera inferior

La navegación principal sigue siendo:

```txt
[Inicio] [Precios] [Vender] [WhatsApp] [Más]
```

### 4. Mantiene Carniza arriba de la botonera

Carniza sigue presente, pero no compite con la navegación inferior ni con los botones principales.

## Qué NO toca

- Registro.
- Web de Arranque.
- Web pública.
- Crear oferta lógica.
- Oferta rápida lógica.
- Oferta con descuentos lógica.
- Vender urgente lógica.
- WhatsApp lógico.
- Panel Admin profundo.
- Firebase/Auth.

## Regla UX

```txt
La botonera mueve.
Carniza orienta.
El cuerpo vende.
El header solo aparece cuando ayuda; si estorba, se guarda.
```

## Criterios de test

1. En mobile, Inicio carga con header más compacto.
2. La botonera inferior sigue visible.
3. En Cambiar precios, el header se oculta/compacta y deja espacio de trabajo.
4. En Crear oferta / Oferta rápida, el header no ocupa pantalla útil.
5. En WhatsApp, el header no estorba la acción.
6. Inicio sigue funcionando.
7. Precios sigue funcionando.
8. Vender sigue funcionando.
9. Oferta rápida → WhatsApp sigue OK.
10. Vender urgente → WhatsApp sigue OK.
