# V12.11-D3 — Landing mobile acceso visible

## Objetivo

Asegurar que en mobile la primera vista de la landing muestre claramente las acciones que importan:

- Probar demo.
- Empezar gratis.
- Iniciar sesión.

Este ajuste responde al criterio mobile-first definido para AppPromos: diseñar para el celular real del carnicero argentino, especialmente Android gama media/entrada.

## Problema detectado

En mobile, la barra superior ocultaba los botones `.btn-light` para ahorrar espacio.

Eso ocultaba:

- Cómo funciona.
- Iniciar sesión.

El resultado era que **Iniciar sesión** podía no verse en la primera vista mobile.

## Decisión UX

En mobile:

- Ocultar **Cómo funciona**.
- Mantener visible **Iniciar sesión**.
- Mantener visible **Probar demo**.
- Compactar logo/header para que entren las acciones.
- Agregar un enlace adicional en el hero: “¿Ya tenés cuenta? Iniciar sesión”.

## Criterio comercial

La landing debe permitir tres caminos rápidos:

1. El que quiere probar sin registrarse: **Probar demo**.
2. El que quiere crear cuenta: **Empezar gratis**.
3. El que ya tiene cuenta: **Iniciar sesión**.

## No toca

- App interna.
- Web de Arranque.
- Crear oferta.
- Vender urgente.
- WhatsApp.
- Panel Admin.
- Registro/Login profundo.
- Firebase/Auth.

## Test mínimo

1. Abrir landing en mobile.
2. Confirmar que se ve **Iniciar sesión** arriba.
3. Confirmar que se ve **Probar demo** arriba.
4. Confirmar que en hero siguen visibles **Probar demo** y **Empezá gratis ahora**.
5. Tocar **Iniciar sesión** y confirmar que abre el login.
6. Tocar **Probar demo** y confirmar que entra a demo.
7. Tocar **Empezá gratis ahora** y confirmar que abre registro.
