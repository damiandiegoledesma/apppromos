# V12.13-A — Web pública autogenerada mobile-first

## Objetivo

Convertir la Web de Arranque autogenerada desde el alta de una carnicería en una vidriera pública más linda, clara y mobile-first.

La app interna es para el carnicero.
La web pública es para Pepito/Juanita, el cliente comprador.

## Qué cambia

- `public/web.html` pasa a tener una presentación más cuidada.
- El hero queda preparado para celular: nombre grande, ubicación, teléfono y CTA WhatsApp.
- Las ofertas activas se ven como cards simples y comerciales.
- La lista de precios se muestra en cards compactas por rubro.
- El estado de arranque deja de sentirse vacío o técnico.
- El mensaje “Lista de precios en preparación” queda más humano y con CTA a WhatsApp.
- El botón inferior fijo de WhatsApp respeta mobile y safe-area.
- Se refuerza que la web no publique productos sin precio válido.
- La ruta pública por slug deja de leer datos internos de `businesses/...` y renderiza desde una vidriera pública sanitizada en `publicWebSlugs/{slug}`.
- `web-premium-service.js` genera el payload público seguro al guardar Mi Web y al actualizar datos básicos.

## Reglas de producto

- Web propia sí.
- Datos demo disfrazados de propios no.
- Producto sin precio real cargado no se publica.
- La web pública debe transmitir confianza y simpleza.
- El usuario comprador debe poder tocar WhatsApp rápido.

## No toca

- Login visual.
- Auth profundo.
- Estructura privada de `businesses/...`.
- Precios internos.
- Ofertas internas.
- Vender urgente.
- Panel Admin.
- Firestore rules.

## Test mínimo

1. Abrir una web pública existente con `web.html?slug=...`.
2. Confirmar que carga en mobile sin scroll horizontal.
3. Confirmar que se ve nombre de carnicería, ubicación/teléfono si existen.
4. Confirmar que el botón WhatsApp abre bien.
5. En web starter, confirmar “Lista de precios en preparación”.
6. Confirmar que no muestra precios demo.
7. Confirmar que productos con precio `0`, vacío o inválido no se publican.
8. Si hay precios reales y `showPriceList`, confirmar que la lista se ve responsive.
9. Si hay ofertas seleccionadas, confirmar que se ven como cards y WhatsApp funciona.
10. Confirmar que la app interna no fue afectada.


## FIX1 — Web pública segura por slug

La web pública debe funcionar para Pepito/Juanita sin login.

Decisión aplicada:

- `publicWebSlugs/{slug}` pasa a ser la vidriera pública sanitizada.
- `public/web.html` cuando entra por slug usa solo ese documento público.
- No abre lectura pública sobre `businesses/{businessId}/core/meta` ni `businesses/{businessId}/core/state`.
- `publicWebSlugs` guarda únicamente datos publicables: nombre, ubicación, teléfono/WhatsApp, estado, ofertas públicas y productos públicos con precio válido.
- Los campos internos como dueño, email, notas, billing, módulos o datos admin no forman parte de la vidriera pública.

Para empresas existentes, después del deploy puede hacer falta entrar a **Mi Web** y tocar **Guardar configuración web** para regenerar el documento público con el nuevo payload.
