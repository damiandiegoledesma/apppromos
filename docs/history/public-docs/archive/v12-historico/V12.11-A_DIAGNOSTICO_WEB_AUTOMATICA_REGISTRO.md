# V12.11-A — Diagnóstico Web automática desde registro

## Objetivo

Definir la decisión de producto y arquitectura para que AppPromos cree una web propia desde el registro sin publicar información incompleta o engañosa.

El objetivo comercial no es solo activar una página. El objetivo es que el carnicero sienta:

> Ya tengo mi web propia.

Y que ese efecto lo lleve al primer compromiso fuerte con AppPromos:

> Actualizar mis precios reales.

Cuando el carnicero actualiza sus precios, la lista queda útil para la web, para crear ofertas y para vender por WhatsApp. Ese paso aumenta la probabilidad de retención después del trial.

## Por qué antes nacía apagada

La web nacía apagada porque originalmente Web Premium era un módulo adicional habilitado manualmente desde el Panel Admin y pensado para cobrarse aparte.

Ese criterio cambió: la web propia pasa a ser gancho comercial del trial.

Regla comercial vigente:

```txt
Todos los planes tienen web propia.
DUEÑO tiene web personalizada.
```

## Concepto: Web de Arranque

La web automática no debe publicarse como si ya estuviera completa. Debe nacer como:

```txt
Web de Arranque
```

La Web de Arranque publica identidad real y evita publicar datos dudosos.

Debe mostrar:

- nombre real de la carnicería;
- WhatsApp real;
- localidad/provincia si existen;
- URL pública propia;
- mensaje claro para actualizar precios reales.

No debe mostrar:

- precios demo;
- ofertas demo;
- productos con precio cero;
- productos sin precio;
- datos incompletos como si fueran reales.

## Decisión madre

```txt
La web automática no publica precios demo.
La web automática publica identidad real y empuja a cargar precios reales.
```

## Regla de publicación de productos

```txt
Producto sin precio real cargado = no se publica en la web.
```

La web pública debe mostrar solo productos con precio válido mayor a cero.

Separación correcta:

```txt
App interna = catálogo amplio editable.
Web pública = solo productos reales con precio real.
```

Ejemplos:

```txt
Asado $15.900 → se publica
Vacío $18.900 → se publica
Riñón $0 → no se publica
Producto sin precio → no se publica
```

## Qué debería mostrar la Web de Arranque

Mientras el carnicero todavía no confirmó precios reales, la web pública debería mostrar algo seguro:

```txt
CARNICERÍA LA ESTACA

Tu carnicería de confianza en Venado Tuerto.

Estamos actualizando la lista de precios.
Pedí la promo de hoy por WhatsApp.

[Consultar por WhatsApp]
```

## Primer ingreso sugerido con Carniza

Al primer ingreso después del registro, Carniza debería mostrar:

```txt
Listo, ya tenés tu web propia.

La dejamos preparada con tu nombre y tu WhatsApp.
Ahora actualizá tus precios reales y salís vendiendo.
```

Acciones sugeridas:

```txt
Actualizar mis precios
Ver mi web
Crear oferta después
```

## Estado técnico detectado antes de V12.11-B

El registro ya creaba parte de la estructura:

- usuario Auth;
- business;
- core/meta;
- core/state;
- teléfono normalizado;
- localidad/provincia;
- slug;
- publicWebSlugs;
- publicPhoneKeys;
- productos base;
- savedCombos vacío.

Pero la web nacía apagada:

```js
web: {
  enabled: false,
  slug,
  selectedOffers: [],
  showPriceList: false,
  visibleRubros: [],
  updatedAt: now
}
```

Y el índice público nacía apagado:

```js
active: false
```

Conclusión:

```txt
La web automática no hay que inventarla desde cero.
Hay que activar y ordenar lo que ya existe.
```

## Estado web recomendado

```js
web: {
  enabled: true,
  published: true,
  active: true,
  mode: "starter",
  priceListStatus: "pending_real_prices",
  offersStatus: "empty",
  slug: "...",
  publicUrl: "...",
  createdFrom: "registration_auto",
  createdAt: now,
  updatedAt: now
}
```

## Estados recomendados

### Web creada

La URL existe, el slug existe y la identidad real está cargada.

### Web de Arranque

La web es pública, muestra identidad real y no muestra precios/ofertas demo.

### Web lista

El carnicero ya actualizó precios reales. La web puede mostrar productos con precio válido y ofertas reales seleccionadas.

## Normalización de nombre público

Ejemplos:

```txt
Carnicería Carnicería López → CARNICERÍA LÓPEZ
carniceria la nueva → CARNICERÍA LA NUEVA
La Estaca → CARNICERÍA LA ESTACA
```

Slug y nombre visible deben ser cosas distintas:

```txt
Nombre visible: CARNICERÍA LA ESTACA
Slug: carniceria-la-estaca-3462505050
```

## Qué no debe tocar esta etapa

No tocar:

- Crear oferta;
- Oferta rápida;
- Oferta con descuentos;
- Vender urgente;
- WhatsApp;
- backend Python;
- SQLite;
- borrado real Auth.

## Criterios de aceptación futuros

1. Registro nuevo crea usuario correctamente.
2. Registro nuevo crea business correctamente.
3. Se crea slug único.
4. Se crea publicWebSlugs activo.
5. Se crea publicPhoneKeys.
6. La web pública abre.
7. La web muestra identidad real.
8. La web no muestra precios demo.
9. La web no muestra productos con precio 0.
10. Crear oferta / WhatsApp siguen intactos.
11. Demo sigue funcionando.
12. Consola sin errores rojos nuevos.

## Frase final

```txt
La Web de Arranque vende la prueba gratis.
La actualización de precios engancha al cliente.
La web pública no debe publicar nada incompleto.
```
